## Required fixes

1. Apply the recovery matrix in `commit` and `release` the way reserve already does. Keep the outbox write first. Map CONFLICT to GET of the same quadruple while retaining the prior durable state; mismatch must not mutate that state; EXPIRED must persist the full remote tuple and project `RECONCILIATION_REQUIRED` with a non-empty `reconciliation_reason`; 410 and unknown reconcile must never re-POST. Add tests whose commit/release scripts return PENDING, 409, mismatch, EXPIRED, and 410. The current scripted adapter hides this.
2. Honor `NEW_OPERATION_SAME_SALE` and mismatch `RETAIN_DURABLE_EVIDENCE` inside `beginReserve`. A second call with the same operation id after 404, validation/stock/stale catalog, or payload mismatch must not POST again. Cover that with a second-call assertion. Today only 410 has that assertion.
3. Make `TransportStoreCoreInventoryAdapter.reconcile` read `data.present` and `data.unknownReceipts` from the pinned envelope (`reconcile-unknown.json` already has that shape). Keep unknown from authorizing a re-POST. Stop substituting the synthetic quadruple `ci-reconcile` / `op-reconcile`; reconcile's required caller header is `X-Client-Instance-Id`. `getOperation` also labels every GET as `RESERVE`, so commit/release recovery cannot trust that parse until the kind is taken from the call.
