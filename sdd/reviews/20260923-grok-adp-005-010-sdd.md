## Recovery matrix (spec vs policy vs saga)

| Outcome | Technical spec | `StoreCoreRecoveryPolicy` | `LocalSaleSagaService` |
|---|---|---|---|
| Uncertain reserve | GET same quadruple before another POST | not an error code; transport GET on thrown POST | crash keeps `PENDING_RESERVATION`; intent/outbox already stored |
| PENDING | inbox, no fabricated receipt | `RETAIN_PENDING` | reserve path returns pending, evidence null |
| RESERVED on reserve | store durable tuple | `RETAIN_DURABLE_EVIDENCE` | `markReserved` |
| EXPIRED | full tuple, `RECONCILIATION_REQUIRED`, non-empty reason, never re-POST | `RECORD_RECONCILIATION_REQUIRED` | reserve path matches; reason and receipt asserted |
| NOT_FOUND / 404 | new operation id, same sale | `NEW_OPERATION_SAME_SALE` | stays pending; does not mint a new operation id |
| CONFLICT | reserve stays PENDING; commit/release keep prior RESERVED/COMMITTED; bounded same-quadruple retry | `GET_SAME_QUADRUPLE` | reserve GETs then applies the receipt (can become RESERVED); commit/release ignore the policy |
| payload mismatch | no mutation | `RETAIN_DURABLE_EVIDENCE` | reserve stays pending |
| 410 `OPERATION_RETIRED` | never re-POST | `NEVER_REPOST` | reserve marks retired; second reserve throws |
| reconcile unknown | never re-POST | projection `unknownAuthorizesRepost()` is false | scripted reconcile only; HTTP reconcile returns every known receipt as unknown |

Reserve-path PENDING, EXPIRED, mismatch, 410, and unknown-reconcile match the tests. Commit/release and "new operation id" do not. HTTP 429 on POST retries the POST (`shouldRetryPost`) without reading envelope `retryable`. Evidence ADP-005 says an uncertain POST GETs and does not re-POST; that is true for a thrown POST, not for 429.
